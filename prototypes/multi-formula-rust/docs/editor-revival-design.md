# 交互恢复设计：文档编辑控制器 + 公式编辑核心（v1.1）

> 状态：与作者讨论后收敛的决策记录（尚未实现、未运行）。v1.1：开放项 O1–O7 全部定稿，见 §11。目标：把"恢复旧原型交互逻辑"的目标、边界、协议与决策固化下来，避免开发过程中再次出现"沟通不到位"导致的交互丢失。
>
> 关联原型：
> - 旧原型 `prototypes/lyx-rust` —— 提供被参考的交互逻辑（LyX 式结构化编辑），但其 crate/页面/WASM **不直接复用**。
> - 新原型 `prototypes/multi-formula-rust` —— 本文的落点。

## 0. 一句话目标

在**不改变新原型数据/渲染架构**（源码即文档真相、深度 Typst 引擎、双模式、SVG 缓存、宏投影）的前提下，把公式编辑从"文本补丁 + 重解析"恢复为**有状态的结构化编辑**：新增浏览器内同步执行的 **公式编辑核心** 与 **文档编辑控制器**，交互语义对齐旧原型。

## 2. 分层与数据流

```
                        浏览器（页面内）
   [新增] 文档控制器(wasm)   统一光标/undo/模式；按键路由到各上下文
   [新增] 公式编辑核心(wasm)  公式树+结构光标；按键→规范化公式源码（待 flush）
                             绘制/事件转发（沿用现状，不含语义）
                        原生服务端（不变）
   Document:  源码+revision+节点/宏/公式索引+投影（含符号表查询，见 §附 A）
   Engine:    编译线程、SVG 缓存、预览；入口目录内资源
   LSP 服务：正文 + 宏框 + 公式命令部分的补全/诊断（O6）
```

显示模式内一次按键的数据流：

```
按键 → editor-core(本地树+光标, 同步) → 规范化公式源码
     → 文档控制器 → 补丁 {revision, formula.body.start, formula.body.end, canonical}
     → POST /api/edit（仅该公式区间）→ 服务端 revision+1、重索引、去抖编译
     → 返回（现阶段可沿用全量 document_json；scope 化响应为开放项）
```

一致性由"规范化写回"锁死：服务端源码区间每轮被核心序列化覆盖 ⇒ 服务端重投影与本地树天然一致（旧核心测试已验证 roundtrip：`load(write(tree)) == tree`）。**不变量：写回必须覆盖整个公式 body 区间，不允许半区间脏补丁。**

## 3. 框模型与文档级导航

文档流 = 正文文本 run、宏框、公式框交错排列。文档级光标 = 文本偏移 或 (框 id + 框内状态)。

| 事件 | 正文文本 | 宏框（文本框） | 公式（预览模式） | 公式（显示模式） |
|---|---|---|---|---|
| ← / → 到达左/右边界 | — | 进入框首/尾 | **整框跨过** | **进入框首/尾**（类似旧字符串框） |
| 框内边界再按 ← / → | — | 退出回正文 | — | 退出回正文 |
| 框边界退格/删除 | — | 删整个宏（有未提交草稿先阻止/确认） | 删整个公式 | 删整个公式（框内另有结构语义） |
| Shift+方向（选中） | 文本 | 整框选中 | 整框选中（同字符） | 进入框内结构选区 |
| Enter | 换行 | 应用宏源码（一条文本补丁） | — | 顶层无草稿 → flush+关会话+切预览；有草稿 → 先按旧语义确认草稿 |
| 点击 | 置光标 | 进入编辑 | **切显示模式** | 定位停靠点 |

预览模式下的公式与普通字符无异：跨过 = 一步越过整个区间；删除 = 整段删；选中 = 作为整体包含进选区（语义同旧原型"SVG 原子、整块选择删除"）。

## 4. 公式显示模式会话

### 4.1 状态与事件

- 会话 = 公式框在显示模式下的一次打开：**点击预览图**或从文档边界方向键进入 ⇒ 按文档当前内容 `import(formula_source, visible_lets, display)` 打开。
- 会话内按键同步作用于本地树（LyX 手感）；**多个公式可同时处于显示模式**，各自会话独立。
- 会话结束 = 顶层 Enter（flush → 切预览）；会话期间焦点移走 ≠ 结束（flush 后保留显示模式，见 4.3）。

### 4.2 Flush 协议（定稿）

**flush 定义**：用会话树的规范化序列化整体替换该公式 body 区间，走 `/api/edit`；每次 flush = 一个文档 revision + 一个文档级 undo 单元。

| flush 触发 | 行为 | 产生补丁 |
|---|---|---|
| 直接键（字母/数字、`/`、`^`、`_`、退格等不进特殊模式的键） | 每键一次 flush | 是 |
| 命令轮 `\` … Enter | 轮内零 flush；Enter 解析成功 → flush 一次 | 是（成功时） |
| 命令轮 `\` … Esc | 取消草稿，恢复原内容 | 否 |
| 字符串轮 `"` … `"`（或轮末） | 轮内零 flush；闭合/退出 → flush 一次 | 是 |
| 焦点离开公式框（点正文/其他框/宏框） | 立即 flush 当前轮（见 4.3） | 是 |
| 顶层 Enter（无进行中草稿） | flush → 关会话 → 切预览 | 是（通常无未落定内容） |

**不变量**：
1. flush 出去的源码**永远是合法 Typst 公式**（完整结构树序列化；草稿/未完成内容从不落文档）⇒ 公式显示模式中不再出现"修复框"兜底（区别于当前正文式编辑）。
2. 规范化整段替换只发生在该公式区间内；文档其他区域、其他框不受影响。
3. 序列化器与解析器必须满足 roundtrip：`import(write(tree)) == tree`（核心不变量，需测试锁死）。

### 4.3 焦点离开时的进行中草稿（O1：已定）

光标离开公式框时若有进行中草稿（命令/字符串轮未闭合）：**按"可解析成合法结构则提交（等价自动 Enter），否则视同 Esc 取消、保留原内容"，然后 flush**。实现时按此规则执行，不再另行确认。

### 4.4 轮内按键归属（O4：已定）

命令/字符串轮进行中，`←`/`→`/`Home`/`End`/退格等按键**在轮内移动/编辑草稿**（与旧草稿语义一致），不退出轮；退出轮只发生在：命令 Enter/Esc、字符串闭合/Enter、以及 4.2 表中的 flush/焦点离开规则。从公式框外进入框内不受轮状态影响。

## 5. 公式编辑核心 editor-core

新 crate（建议 `prototypes/…/editor-core` 或新原型内子 crate），依赖仅 `typst-syntax`（与两原型共用同一固定版本）+ serde。native 全量 `cargo test`，wasm 供页面。**editor-core 不依赖完整 Typst 库、不做符号表查询**（见 §附 A）。

### 5.1 模块

| 模块 | 职责 | 备注 |
|---|---|---|
| `tree.rs` | `MathAtom`/槽位/结构光标路径 | 对齐旧原型 `math.rs`；Raw 保留源码字符串 |
| `actions.rs` | Action 状态机：输入/按键/草稿/选中 | 语义照旧（§5.2），undo 记录不设（D10） |
| `parse.rs` | 公式源码 + 可见宏定义 → 树 | 对应旧 `parse_document`；由服务端提供"可见 let 前缀" |
| `serialize.rs` | 树 → 规范化 Typst 源码 | 对应旧 `write_atom`/`write_cell`；只序列化本公式 |
| `view.rs` | 会话内草稿/轮视图 + 停靠点 | 结构视图、Raw 图片、宏展开布局由服务端投影/SVG 缓存喂（O2） |

### 5.2 行为契约（回归清单，语义移植自旧原型测试）

- 普通输入逐个插入 Char，不合并、不改写（`<=+` 三节点）；单字符显示字形映射不改源码。
- `/`：选区/左邻对象入分子、光标进分母；`^`/`_`：创建/进入上下标槽。
- 命令草稿：空格/括号/反斜杠保留、左右键移动草稿光标（O4）、**只有 Enter 确认**（解析成树）、Esc 恢复被替换原文；Tab/补全只填候选不确认。
- 退格：槽首解散父结构、只保留当前单元内容；Delete 跨对象/整块（Raw、宏调用整块）。
- 空槽 = 持久状态（显示为 □ / 浅边框），序列化时写合法占位（`""`）；不允许出现 `frac(1, )` 类不合法源码。
- 字符串框 / 对齐公式 / Tab 槽切换 / 行列增长（按需移植）。
- 复制选区得 Typst 源码；粘贴进入命令草稿、Enter 确认、Esc 恢复被替换选区。
- 显示字形映射只改视图（`-` → `−` 等），不改树与源码。

### 5.3 序列化（D6）

可接受的规范化改写（仅限进过显示模式的公式）：`1/2 → frac(1, 2)`；`x^2 → x^(2)`；普通对象间补空格。实现细节对齐旧 `write_atom`/`write_cell` 的分词/空格规则，但以 editor-core 自有实现为准（不拷旧代码）。

### 5.4 Raw 与渲染

- 会话内 Raw/Script 中心对象的 SVG 与 limits/stretch 布局**继续读服务端 SVG 缓存**（公式 cache_id 前缀键），editor-core 不编译、不求值。
- 渲染失败：保留源码；支持从两侧方向键进入源码草稿、Enter 重试、Esc 恢复（旧行为）。
- 模式切换刷新协议见 §7。

## 6. 宏

### 6.1 就地 AST 与捕获解析

- 公式树中宏调用 = 一个节点（宏名 + 一份实参槽），**不保存展开副本**。
- 展开在**显示时**按定义体绑定实参生成视图；定义体内嵌套调用按**定义处环境**解析——由文档宏索引的 `captured EnvironmentId` 提供（`prototypes/multi-formula-rust/src/macros.rs`）。
- 宏被重定义 = 文档 revision+1 → 重索引 → 重新投影，旧解析自然作废。**不需要旧核心的 `TemplateCall{definition}` 版本注册表**。
- 会话打开时向服务端取"该公式可见的 #let 序列"作为宏上下文快照；会话内宏上下文变化（宏框编辑提交）→ 会话 epoch 失效 → 需要时重开/重新 import。

### 6.2 可展性 + 自引用（唯一静态环）

- 可展条件（沿用）：直接返回数学公式/值的位置参数宏；参数在 Raw 中、未显示参数、默认/命名/可变参数、动态宏体 → 不可展。
- **自引用检查**：具名闭包 `#let f(x) = …` 把**自身名字绑定进定义时作用域**后，若体内对宏名的引用解析到自身 ⇒ 不可展，`reason = "函数体引用自身，展开无法终止"` ⇒ 调用点**整段 Raw**（含实参，不做结构编辑）。
- 论证：顺序 `#let` + 词法捕获下，定义只能引用更早的定义；互递归需要 A 在 B 前且 B 在 A 前，矛盾；块/动态代码已归 opaque/uncertain ⇒ **静态子集里环只可能是自引用**，无需引用图环检测。
- **需修复的现存缺陷**：当前 `macros.rs` 未把闭包自身名字加入作用域，遮蔽场景下（先 `#let f(x)=$x^2$`，再 `#let f(x)=$f(#x)+x$`）体内 `f` 会被投影错误解析为**前一个** `f` 并展开，与 Typst 语义（自引用自身）不一致。修复后补回归测试。
- 规模预算（节点/深度）保留为第二道防线，只管超长非递归展开链，不是环的兜底。

### 6.3 会话内宏展开机制（O2：已定）

**采用 (ii)**：宏展开视图完全由服务端投影渲染——直接键已逐键 flush，视图本就来自服务端返回的投影，展开随投影即时送达（服务端展开开销可忽略）。editor-core 不做本地展开，避免展开器在两端各实现一份。若将来发现往返延迟影响手感，再评估引入本地展开。

### 6.4 宏框（O3：已定）

- 宏框 = **普通文本框**（textarea 形态），不引入特殊结构编辑；其"框"属性仅指参与文档流的原子跨过/删除/选中（§3）。
- 文本编辑与 LSP 同步：补全/诊断随输入实时更新（LSP 直接对草稿文本做校验，不要求先提交到文档）。
- **失焦动作**：执行 LSP 校验；编译不过 ⇒ 该宏框**标红**，鼠标停留显示报错信息。
- Enter 应用（写入文档一条文本补丁）、Escape 离开；已应用修改按 6.1 使相关公式会话 epoch 失效。

## 7. 双模式切换与 SVG 缓存刷新

- 显示 → 预览：光标在公式内且处于 **top level**、无进行中草稿 → Enter ⇒ flush、关会话、切预览；**刷新该公式及其内部 Raw 的 SVG 缓存**（走现有 `POST /api/refresh-svg {formulas:[node]}`，服务端刷新公式与公式内 Raw 键）。
- 预览 → 显示：鼠标点击预览图 ⇒ 按文档当前内容重新 import 开会话；**同时刷新该公式及内部 Raw 的缓存**。
- 有进行中草稿时按 4.2/4.3 先行 flush（或取消）再切换。
- 冻结/过期状态沿用现状：`stale/pending/error` 展示与"全部更新 SVG"保留。

## 8. Undo/Redo（D10、O5）

- **单栈**：文档级补丁栈；**颗粒度 = flush**——每次 flush 一个 undo 单元，命令/字符串轮整轮一个单元，直接键逐键各自成单元；**不做 typing 合并**。
- 命令/字符串轮内部：轮未 flush，undo 不跨轮生效；Esc 承担轮级"整体放弃"。

## 9. 会话失效与并发

- 所有补丁沿用 `revision` 校验（现状已有：旧版本拒绝）。
- 会话打开后，若文档在**本公式区间外**被编辑（正文、其他框、宏框）→ 该公式源码区间未变则可继续（焦点离开 flush 后投影已同步）；若**区间内**被外部编辑（全文源码框直接改写该公式）→ 会话失效，重开时按新内容 import（冲突处理与提示在实现期定）。
- 宏上下文（可见 #let）变化 → 会话 epoch 失效，规则见 6.1。

## 10. 分阶段路线图

1. **editor-core（native）**：树/光标/解析/序列化 + §5.2 行为契约测试 + roundtrip 不变量测试；不碰页面与服务端。
2. **wasm + 公式显示框接入**：editor-core 编 wasm；替换当前 `FormulaEditor` 的按键语义来源；flush 协议落地（每轮补丁走 `/api/edit`）；服务端投影回归验证（补丁后投影与本地树一致）。
3. **文档控制器**：框进出/选中/删除、宏框（O3）、模式切换与 SVG 刷新协议、文档级 undo、会话失效规则。
4. **LSP 与打磨**：LSP 接入范围 = **正文 + 宏框 + 公式命令部分**（O6）；scope 化响应（避免每键整文档重发）；性能。

| O7 投影符号表查询 / 单字符糖 | 见 §附 A：符号名查 scope（服务端投影）；单字符/ASCII 糖用 typst-syntax 的 `MathShorthand::LIST`；不引入用户 JSON，editor-core 不引入完整 Typst 库。 |

## 12. 剩余开放项（实现前需定）

- 补丁响应是否 scope 化（现阶段沿用全量 `document_json` 的可接受性，性能实测后定）。
- 全文源码框直接改写公式区间的冲突处理交互细节（§9）。
- 会话内宏展开若未来改走本地 (i)（现按 O2 用服务端投影）：本地字形来源 = 服务端投影已带的字形标注 + `MathShorthand::LIST`（附 A），无需用户 JSON。

## 13. 验证策略

## 附 A：O7——显示字形的引擎来源：scope 符号名查询 + MathShorthand 单字符糖

公式显示所需的字形来自引擎的**两处**数据，都不需要用户自设 JSON（`symbols.json` 取消）：

**1. 符号名 → scope 查询**（服务端投影，`projection.rs`）：

```rust
static LIBRARY: LazyLock<Library> = LazyLock::new(Library::default);   // 完整 Typst 库
...
ast::Expr::MathIdent(_) | ast::Expr::Ident(_) => {
    // 先查宏（macros.visible），再查内置 math 作用域
    if let Some(binding) = LIBRARY.math.scope().get(spelling) {
        if let Value::Symbol(symbol) = binding.read() {
            out.kind = ProjectionKind::Symbol;
            out.text = Some(symbol.get().into());   // 只取字形，不动源码
        }
    }
}
```

- 遇到 `alpha`/`times`/`arrow.r`/`integral` 等名字，问 Typst `math` 作用域"是否绑到 Symbol 值"，命中则把 Unicode 字形（`α`/`×`/`→`/`∫`）写入 `text` 字段供显示。**只改显示，源码不变。**
- scope 的键是**符号名**（typst-library 从 `codex::SYM` 装载，`symbols.rs`；codex `sym.txt` 无单字符键），所以"-"这类裸字符键**不在 scope 里**，单字符转换集合无法从 scope 枚举。

**2. 单字符/ASCII 糖 → `MathShorthand::LIST`**（`typst-syntax/src/ast.rs:1010-1049`，公开 const）：

- 这正是用户要的 `-`→`−` 所在的层：数学模式词法把 `*`/`-`/`~` 及 `<=`、`->`、`!=` 等序列产成 `MathShorthand`（`lexer.rs:673-706`），求值时转为对应 Unicode Symbol（`typst-eval/src/math.rs`：`Symbol::runtime_char`）。
- 表中单字符键 = `-`→`−`、`*`→`∗`、`~`→`∼`（即旧 symbols.json 中 `-`/`*` 两项，`~` 比旧表还全）；多字符键（`<=`→`≤`、`->`→`→`、`!=`→`≠`…）同样公开可枚举。
- **editor-core 唯一依赖就是 typst-syntax** ⇒ 单字符显示糖直接引用该表（键长为 1 的项），零 JSON、零新增依赖，且随固定引擎版本自动同步。
- 实现采用 **C 变体**（O7 决议）：editor-core 启动/首次渲染时遍历一次 `MathShorthand::LIST`，把键长为 1 的项建成 `char → char` 映射（可顺带建整表备查），之后逐字符 O(1) 查表。实测三种策略约 8–17 ns/字符（单键 <0.02 µs、50 字符公式 <1 µs），性能差异可忽略；选 C 是为了不硬编码、不随引擎漂移。

**边界与分层**：

- 显示字形分三层，别混淆：① 符号**名**→字形（scope，服务端投影）；② ASCII**字符糖**→字形（`MathShorthand::LIST`，typst-syntax）；③ 数学字母**字体斜体**（`math-font.js` 的 `mathGlyph`：`a`→`𝑎`，纯字体/视图层）。
- 单字符糖做即时字形提示是安全的：Typst 数学模式本来就把 `-` 当作 `−` 语义（eval 层如此），编辑器按表显示与最终排版一致。
- 多字符糖（`<=`、`->`…）**不做键入时即时合并**（遵守 §5.2"普通输入不合并"原则）；其最终形式由解析/命令路径决定——`MathShorthand` 节点在投影中继续保留 Raw 交引擎渲染（`projection.rs:237-240`），维持现状。
- scope 查询只留在服务端投影（O2 推论）：`Library::default()` 是完整 Typst 库，编进 wasm 代价大；editor-core 不引入它。若未来 editor-core 需要本地显示符号名（非字符糖）字形，来源是服务端投影每次 flush 已随投影返回的 `text` 字形标注，而不是再引入一份字典。两端唯一一致性要求是共用同一固定 typst-syntax 版本（两者已 path 依赖 `../typst-engine`）。

## 附 B：上下标位置 / operator / stretch 功能覆盖核查（旧原型 vs 新设计）

核查日期：设计 v1.1 讨论期；结论经作者修订，见 B.0。

### B.0 作者定调（修订）

- **operator 不做特殊设计**：当初提出 operator 特殊处理，目的就是上下标（limits/scripts）分类；该分类现由 Typst 引擎布局直接承载，operator 不作为独立设计维度（遗留的显示/输入琐项见 B.2）。
- **上下标位置大概率无问题**：旧原型正是读引擎返回的位置（`ScriptsItem`）；新原型与引擎同进程、同一次编译，直接读位置比旧版更顺——几何推断仅作回退。仍以 B.4 用例回归兜底。
- **stretch 暂定不做专门处理（存疑待验证）**：`stretch(...)` 记为 Raw、随公式整块编译/刷新；Raw 片段取自整文档的最终布局，理论上标签变宽后轮末 flush + 公式级刷新（含内部 Raw，§7）即自动得到新长度——等价旧版"靠刷新 stretch 拿真实长度 SVG"。是否成立、以及"失焦刷新中心符号与上下标"是否即所需触发，待引擎实测（B.4）。

### B.1 上下标位置（limits/scripts）

| 旧原型能力（出处） | 新原型现状 | 新设计覆盖 |
|---|---|---|
| 分类来自 Typst 真排版（`resolve_equation` → `ScriptsItem.top/top_right/bottom/bottom_right`），覆盖默认（行内/行间差异）、显式 `limits(A)`/`scripts(sum)`、自定义 `math.op("…", limits: true)`、`sum_()` 空槽（native-adapter 测试） | 全文档编译后推断 limits/side；当前实现为**槽位几何推断**（`svg_cache.rs`：中心对齐 ≈3pt 判 limits，否则 side），倾向改为**直接读引擎 IR 位置**（几何仅回退） | 与旧同源（引擎位置），且与引擎同进程同编译更易获取；低风险，B.4 回归兜底 |
| 仅顶层 Script；嵌套（分式内、脚本内）不查询（旧 `view.rs` `path.is_empty() && !has_draft`） | 对**所有** Script 投影目标推断，无深度/嵌套保护 | 几何来自最终布局，嵌套可能更正确；需回归确认分式内 `sum_i` |
| 空槽 `sum_()` 仍返回正确位置 | 空槽=`""`，可能无可见 fragment → 推断缺失回退 side | **缺口**：需验证/处理空槽按 Typst 语义定位 |
| 未决/失败：右侧回退 + 底部状态条（等待/成功/错误）、防抖 160ms、单在途、按上下文缓存、旧响应不覆盖 | `pending/error/stale` 标注 + hover 文案；无独立状态条；无 layout 前默认 side | UI 差异：保留或明确接受；缓存语义已有 |
| 左附件/多合一不可对应 → error 保留原结构 | 无显式检测，推断失败即缺 layout | 风险低（几何天然不误映射），回归覆盖即可 |
| 结果只改显示，不写树/撤销 | layout 只是缓存字段，不写源码 | ✓ 一致 |

### B.2 operator —— 不再作为独立设计维度（见 B.0）

| 旧原型能力 | 新原型现状 | 新设计覆盖 |
|---|---|---|
| 单字符运算符显示糖 `-`→`−`、`*`→`∗`（config 字典） | 由 `MathShorthand::LIST` 派生（C 变体） | ✓（附 A） |
| 运算符/数字/函数名正体、字母斜体、字符串正体 | mathGlyph + CSS relation/binary 类 | editor-core 视图沿用；§5.2 契约补一句"正体/间距类继承现有视图规则" |
| 普通输入不合并运算符（`<=+` 三节点） | §5.2 首条已列 | ✓ |
| 词级移动按数学类分组（Ctrl+←/→，旧 `math_class`/`move_word`） | 契约未列 | 与上下标无关的旧手感项：是否保留按需定；若要，显示模式方向键语义补 Ctrl 词移动 |
| 位置分类不按 operator 名称判断 | 几何/真布局，不查名称 | ✓ 一致 |
| 未知函数/符号名整体 Raw、由引擎渲染（`sin`/`lim`/`lr`/`text`） | Raw 片段 / 投影 Raw | ✓ 一致 |

### B.3 stretch

| 旧原型能力 | 新原型现状 | 新设计覆盖 |
|---|---|---|
| 中心字形随附件宽度伸展：先整体量 limits 宽设伸展参考，再导中心 SVG + width/height | `stretch(...)` 记为 Raw，随公式整块编译/刷新；无专门 stretch 路径 | **暂定：无需专门处理（存疑待验证，见 B.3 末）**：Raw 片段取自已完成的整文档布局，若含伸展则轮末 flush/刷新即自动更新长度；若实测不含，再在收集端补中心测量导出 |
| 附件仍可编辑、无 SVG↔源码反向定位 | base 槽/附件槽照旧编辑源码 | ✓ |
| 独立 `stretch(...)` 无附件 = 普通 Raw | `stretch` 不在模板名 → Raw | ✓ |
| limits/scripts 与 stretch 联动（伸展参考宽度取附件） | 由真布局承载 | ✓（语义，依赖上一条验证） |

**存疑记录（作者要求，待验证）**：stretch 的专门处理可否并入"上下标失焦时刷新中心符号与上下标"；Raw 整块刷新是否自动带正确伸展长度。在 B.4 stretch 用例实测前保持存疑；结论只影响是否需要补收集端导出。

### B.4 建议引擎回归用例（移植自旧 native-adapter / operator-limits 测试）

- 行内/行间：`$sum_i^n$` 切换后位置跟随 Typst；`$lim_(x->0)$`；`$scripts(sum)_i^n$`；`$limits(A)_i^n$`；`#let my = math.op("my", limits: true)` 后 `$my_i$`；`$sum_()^()$` 空槽；分式内 `sum_i`。
- stretch（存疑项首验）：`$stretch(arrow.r)^("a much longer label")$` 在显示/预览/编辑模式下：Raw 片段是否含伸展长度；编辑标签变长后轮末刷新是否自动更新中心宽度；附件可编辑性；嵌套情形（旧原型本不支持嵌套，照实记录差异）。
- 叠加 §7 缓存协议：刷新/失败/冻结语义。
