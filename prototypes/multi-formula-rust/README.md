# Typst 文档与公式编辑投影原型

这个原型直接依赖共享的 `../typst-engine`，不依赖 `lyx-rust` 的 crate、WASM、页面或 native-adapter。它采用 **Typst engine + 编辑投影**：语言解析、求值、样式、作用域执行和排版归 Typst；本原型只管理源码索引、可编辑槽位、交互状态与已排版片段。

## 构建与启动

在本目录运行：

```powershell
.\build.cmd                 # 默认离线构建
.\build.cmd --online        # 缺少缓存时，允许下载引擎/依赖
.\start.cmd                 # 离线构建后启动
.\start.cmd examples\context.typ
```

打开 [本地编辑页面](http://127.0.0.1:4321)。服务不会主动打开浏览器。
只想运行已构建的程序：`target\debug\multi-formula-demo.exe 4321 examples\context.typ`。

- 需要 Git、支持依赖版本的 Rust 工具链与 Windows 本机链接器；不再需要 WASM 工具链或 Tinymist。
- 公共引擎位于 `prototypes/typst-engine`，固定提交为 `59b5999da8e74e74583069408d2564fc1f9bc973`。只有目录缺失且使用 `--online` 时才 clone。
- `prepare-engine.ps1` 检查提交并幂等应用 `engine-patches/math-origins.patch`；不重置已有 checkout，不覆盖其他原型留下的改动。版本或补丁冲突时停止，留给用户处理。
- 旧的解析器版 `Cargo.lock` 已移除。首次构建由 Cargo 按新依赖图重新生成；脚本不使用 `--locked`。依赖缓存不足时用 `--online`。
- 本次重构未运行构建、测试或浏览器验收，按用户要求交由用户执行。

## 页面操作

1. 在文档编辑页放置光标，点击“添加宏”“添加行内公式”或“添加行间公式”。宏行只加背景和编辑下划线，公式以细框包裹。
2. 宏输入完整的 `#let`，Enter 提交，Shift+Enter 换行。公式的上下文索引在进入编辑前已经随文档建立。
3. 公式显示模式直接使用编辑投影；输入 Typst 数学文本，`\` 打开命令输入，输入 `frac`、`sqrt`、`root`、`mat`、`abs` 或本地宏名称后 Enter 插入。`^` / `_` 插入空上下标槽。
4. 方向键移动，Tab 切换槽位，Shift+方向键扩展源码选区。点击空槽输入；Raw 单击、字符串双击可在原位置编辑源码，Enter 提交。展开宏的模板正文只读，参数仍可编辑。
5. 公式内 Enter 只切换到预览模式，不是保存或离开的前提。可同时展开多个公式，点击正文/其他公式或从边界按方向键即可转移焦点，原公式仍保持显示模式。预览 SVG 为原子节点，左右键跨过，点击重新进入显示模式。
6. 宏、Raw、命令和未完成公式的局部草稿可以失焦保留，不锁住其他区域。Raw/宏源码仍以 Enter 应用，Escape 可以退出当前编辑位置；全文源码框的 Enter 则应用整份源码。
7. 页面下方的全文预览持续自动编译；上方公式/Raw 的 SVG 是独立的后端保留缓存。创建节点、应用 Raw 源码、显示/预览模式互换时刷新对应公式。编辑宏、正文或 show 不自动替换所有旧 SVG，点击工具栏的“全部更新 SVG”可重新读取外部依赖并更新全部缓存。

这是架构原型，不是原编辑器交互的逐项迁移：正文编辑页保留非公式部分的 Typst 源码表示；完整排版在下方预览。显示模式恢复了共享 New Computer Modern Math 字体、数学斜体字形、正体字符串框和伸展根号；Raw 按实际片段的文字字号归一到编辑字号。上下限位置尝试从同一次布局的槽位边界推断；重复/不可追踪的实例回退到侧边上下标。这个几何提示不是完整数学排版器，显示模式仍不承诺与 Typst 像素一致。

结构边界直接删除可能产生未完成语法，此时保留原位源码修复框，修复后 Enter 恢复投影。后端继续索引 Typst 容错语法树里可恢复的其他公式；错误 let 作为不透明边界，不继续不安全地展开宏。但若未闭合的分隔符让解析器把后文吸入同一节点，不能凭空保证后文原来的结构仍可识别。尚无结构化撤销栈。

会话编辑只保存在内存，不自动覆盖打开的文件；需要保存时复制源码框的完整内容。

## 一份源码，三个消费者

```text
Document: typst_syntax::Source（唯一可编辑源）
├─ 编译线程：Source 的引用计数快照 → Typst → PagedDocument / Frame
├─ MacroIndex：本文件 let + 词法作用域的 arena 索引
└─ Formula：源码 NodeId + EnvironmentId + Projection
   ├─ 来源：已有 Typst 节点 / UTF-8 字节范围
   ├─ 结构：分数、上下标、根式、矩阵、宏展开的槽位
   └─ 浏览器状态：光标、选区、空槽、命令输入、Raw 编辑草稿
```

Typst 的 `ast::*` 是现有无损语法树的类型化视图。这里不再维护另一套数学语言解析器，也不把投影序列化回整段公式。一次编辑是 `{revision, start, end, text}` 的原源码补丁，所以范围外的注释、空白、写法和嵌套结构保留。

同一个编辑分数既可来自 `a/b`，也可来自 `frac(a, b)`，但它们仍引用各自的原始节点，不强制改写成统一语法。空槽目前用合法 Typst 空字符串 `""` 占位，输入时替换该范围。

主要模块：

| 模块 | 职责 |
| --- | --- |
| `src/document.rs` | 拥有 Source、源码节点索引、版本检查及原子更新 |
| `src/macros.rs` | 有序 let、词法作用域与闭包定义时环境的静态索引 |
| `src/projection.rs` | 直接读取 Typst AST 视图，生成带来源引用的编辑槽 |
| `src/engine.rs` | 常驻 World、字体/文件缓存、去抖编译、编译快照 |
| `src/engine/fragments.rs` | 从已完成 Frame 中收集目标输出并导出 SVG |
| `src/engine/svg_cache.rs` | 保留跨源码版本的 SVG，处理按公式/Raw 的刷新与增量读取 |
| `web/editor.js` | 无解析器的 DOM 公式组件，仅处理编辑交互与槽位绘制 |
| `web/document.js` | 文档输入、三个插入按钮、源码事务、两种公式模式 |

### 索引与宏

`NodeId = {document, revision, index}` 是**快照内引用**，不是跨修改永久不变的节点身份。服务器拒绝旧文档/旧版本的 ID，前端收到新投影后替换引用。`EnvironmentId` 是当前文档快照内的 arena 下标，不能跨版本保留。

新增的 `cache_id` 是会话内的编辑/缓存身份，不用它绕过源码版本校验。范围编辑根据编辑区间映射未受影响及包围编辑的节点，再用节点种类与新范围核对身份；两个内容相同的公式不会共享 ID。整体替换源码会重建身份。SVG 的键是“公式 cache_id + 节点 cache_id”，因此宏模板同一 Raw 在不同公式上下文中的结果不会混用。删除目标会回收对应缓存。

环境是共享的父指针树：每个 let 创建一个新环境版本，块内新建分支，块外恢复父环境。不需要每个公式复制一份定义，也不需要自引用 Rust 结构或 `Rc<RefCell<_>>` 环。

静态展开仅覆盖可明确确定的本地直接值/数学正文及简单位置参数宏；模板来源仍指向定义处，参数投影指向调用处。重复参数可以引用同一个调用参数节点。模板只读，避免用户编辑调用时意外改写宏定义。

不递归扫描 import/include；它们及动态赋值等不确定边界会阻止不安全的静态推断，但其后的本地定义仍能记录。未能静态确定的调用退回 Raw。宏索引不执行 Typst、不代替运行时环境，也不拼接编译前缀。let 初始化器内部的公式不单独列入文档公式列表。

### SVG 与最小引擎扩展

全文中的 `#set`、`#show`、嵌套、闭包与上下文表达式全部交由真正的 Typst 编译器处理。预览不再采用“可见宏 + 公式”的孤立编译。

最终 SVG 并不天然包含每个源码 AST 节点的独立子 SVG。为了建立映射：

- 整个公式利用引擎已有 Equation 元素的布局标签。
- Raw 通过 `World::editor_math_origin(span)` 请求可选来源标记，在数学显示求值边界插入引擎已有的零尺寸、非查询标签。没有新建会改变数学原子分类的 box；默认 World 不启用。
- 扩展只涉及共享引擎的 `typst-library/src/lib.rs` 与 `typst-eval/src/math.rs`；可审阅保存的补丁。它不是重新实现求值器或布局器。
- 全文布局后，遍历 Frame 的标签与绘制项，保留目标项及祖先变换、裁剪、坐标系，排除无关重叠内容，再导出片段。不是拿页面矩形截图冒充对应节点。
- `/api/fragment` 只做已布局结果查询/首次 SVG 序列化，之后缓存；不解析、不求值、不排版。一个源码节点多次输出时返回实例数组。
- 编辑界面现在读取 `/api/svg` 的保留缓存，而不是每次编译都重新取 `/api/fragment`。成功的编译快照可继续变化，未被请求刷新的 SVG 不跟着替换。刷新失败保留旧图并附带错误/版本信息，不把旧图冒充新结果。

边界需明确：任意 Typst AST 节点不一定独立执行/输出；Raw 若不经过数学显示求值边界、被规则移除或替换，或者标签跨页/不成对，可能无可用独立片段，此时明确返回不可用，编辑页显示源码，全文预览仍保留。当前也不提供通用的多次调用实例选择器。不要把 NodeId 理解为引擎天然支持的一一对应 SVG 索引。

来源标记当前附加在求值后的数学显示内容上；非查询标签不会进入普通 query 结果，但会检查内容内部结构的自定义代码仍可能观察到包装差异。因此这个实验补丁不能声称对任意 Typst 程序严格语义透明。测试覆盖常规绘制几何；后续若要处理这种反射用法，需要把来源追踪进一步下沉为布局阶段的旁路信息。

### 更新与性能

- 主文档使用 `Source::edit` / `Source::replace`，由 Typst 增量重解析；编译线程拿到的 Source clone 是引用计数快照。
- 编辑索引/投影目前仍按当前文档重新遍历，并限制宏展开深度与规模；尚未做公式级增量投影缓存。
- 后台单编译线程合并输入，去抖约 180ms。保留标准库、字体、文件缓存及近期 Typst memoization；不在读取 SVG 时重新创建编译器。
- 编译失败保留上一份成功预览并标为旧版本；较旧源码的慢编译不能充当新源码预览。
- `revision` 标识源码，`render_generation` 标识成功编译结果，`svg_generation` 标识保留缓存的变化。外部依赖刷新另有 epoch，过期编译不能覆盖新依赖请求。
- 按需刷新指“从完整上下文的编译结果更新哪些缓存”，不是独立编译选定公式。若当前全文已编译完成，模式切换直接读取它，不增加编译次数；否则等待后台全文编译。后台仍要收集已标记的帧片段，但只为待刷新的目标导出/发布 SVG。
- 缓存接口支持 since 游标，只发送变化的缓存项和当前存活键列表。修改正文不重复传输每个冻结 SVG，也不会因版本变动就撤销所有图片 URL。
- SVG 不是被证明环境无关的结果：show/set、计数器、上下文或外部依赖都可能影响它。冻结是明确的交互策略，缓存保留编译版本，悬停可查看状态；需要一致结果时用“全部更新 SVG”。
- 片段收集仍要遍历全文帧并保存目标绘制项；整页 SVG 按请求生成。不能据此保证任何局部改动都比孤立编译快，页面会显示编译次数和耗时，供实测。

World 支持入口目录内的本地 import/include、图片等资源；禁止越出该目录，不自动下载 Typst Universe 包。当前没有外部文件自动监听，修改依赖后手动刷新。索引始终只管理打开的入口文件。

## 留给用户运行的检查

```powershell
.\check.cmd                 # 离线运行 Rust 单元/集成测试
.\check.cmd --online        # 允许下载测试需要的依赖
.\check-web.cmd             # 可选：Node.js 内置测试，无 npm 依赖
.\start.cmd examples\context.typ
```

测试包括：单一语法树引用、作用域分支、闭包捕获、参数同源投影、内置名称遮蔽、Raw 不复制原文、空槽与原文保真、UTF-8 范围、旧节点拒绝、无效输入修复，以及稳定缓存身份、字符串语义和局部错误恢复。引擎测试覆盖来源标记几何、缓存冻结、仅刷新指定公式/Raw、失败保留旧图、修复后重试和增量缓存读取。可选前端单元脚本覆盖数学字形、偏移映射、独立光标与边界退出，不代替浏览器交互验收。上述新增测试没有由助手运行。

建议手动研究：

1. 编辑示例外层/内层的同名宏，观察作用域和公式重新投影。
2. 改动局部 `#show`：整页自动变化，已有公式/Raw SVG 保留；只切换一个公式的模式，该公式及内部 Raw 更新，其他公式不变；再点“全部更新 SVG”。
3. 等编译停止后在同一公式反复切换显示/预览模式，确认编译次数不因读取 SVG 增长。
4. 在根式、分数、矩阵空槽输入；保留源码框并观察只修改对应范围。
5. 输入暂时无效的 Typst，确认草稿不丢失、旧预览有标记；修复后再观察更新。
6. 同时展开两个公式，在第一个里输入，不按 Enter，点击第二个继续输入；再点击正文连续输入，两个公式都应保持显示模式。
7. 从显示框左右边界进出，在正文里用左右键跨过预览 SVG；在宏或 Raw 中留一份未提交草稿，去另一个位置输入，再回来查看草稿与光标。

API 的范围均为 UTF-8 字节，不是 JavaScript UTF-16 字符下标。`GET /api/document` 返回当前源码、宏索引和投影；`GET /api/state` 返回编译版本、页数和耗时。`POST /api/edit` 提交源码补丁，`POST /api/fragment` 接收 `{node, container?}`，`POST /api/page` 接收 `{revision, render_generation, page}`。

保留缓存接口：

- `GET /api/svg`：当前所有缓存及状态，包含生成版本、pending/error 和存活键；只读。
- `POST /api/svg`，正文 `{ "since": 12 }`：只读取缓存版本 12 后变化的项；首次传 null。前端按 key 合并 entries，按 alive 清理已删除目标。
- `POST /api/refresh-svg`，正文 `{ "revision": 3, "formulas": [NodeId] }`：刷新选定公式及其 Raw/上下限提示。
- 同一接口的 `{ "revision": 3, "nodes": [NodeId] }`：只刷新指定源节点对应的缓存（包括它在不同公式中的投影实例）。
- `{ "revision": 3, "all": true, "dependencies": true }`：重新读取外部依赖，刷新所有 SVG。

这里 NodeId 表示从当前 document 响应取到的实际对象，不是字符串。刷新请求可能立即完成，也可能返回 scheduled 等待编译；读取缓存不会自行发起编译。
